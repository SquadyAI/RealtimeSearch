# SearchAPI 压测工具使用指南

本目录包含了完整的SearchAPI压测工具集，用于测试搜索功能在高并发情况下的性能表现。

## 🛠️ 工具概览

### 核心压测脚本
- **`test_load_performance.py`** - 通用负载性能测试
- **`test_tlb_stress.py`** - TLB (Token Leaky Bucket) 专项压力测试
- **`monitor_performance.py`** - 实时性能监控工具

### 辅助工具
- **`run_load_tests.sh`** - 快速启动脚本
- **`load_test_config.json`** - 测试配置文件
- **`test_search.py`** - 基础功能测试

## 🚀 快速开始

### 1. 环境准备

```bash
# 安装Python依赖
pip3 install aiohttp

# 确保服务已启动
cd apps/backend
npm start
```

### 2. 基础测试

```bash
# 给脚本执行权限
chmod +x run_load_tests.sh

# 运行基础负载测试
./run_load_tests.sh basic

# 运行中等负载测试
./run_load_tests.sh medium

# 运行高负载测试
./run_load_tests.sh heavy
```

### 3. TLB专项测试

```bash
# TLB突发压力测试
./run_load_tests.sh tlb-burst

# TLB持续压力测试
./run_load_tests.sh tlb-sustained
```

### 4. 实时监控

```bash
# 启动性能监控（5分钟）
python3 monitor_performance.py --duration 300

# 自定义监控间隔
python3 monitor_performance.py --interval 3 --duration 600
```

## 📈 测试报告解读

### 实际测试结果分析 (2025-09-22)

#### 总体性能表现
- **总请求数**: 1000 (所有场景累计)
- **成功请求数**: 535
- **失败请求数**: 465
- **整体成功率**: 53.5% ❌ (严重不足)
- **实际RPS**: 4.95 (远低于理论值60)
- **平均响应时间**: 1.732秒

#### 关键问题识别
1. **令牌桶容量不足**: 每个引擎只有10个令牌，高并发下快速耗尽
2. **负载均衡严重不均衡**: serper占87.7%，brave只占12.3%
3. **无429限流**: 所有错误都是502，限流机制未生效
4. **实际RPS远低于理论值**: 理论60 RPS，实际只有4-5 RPS

#### 引擎使用分布
- **serper**: 469次 (87.7%)
- **brave**: 66次 (12.3%)
- **负载均衡比例**: 0.14 (严重不均衡)

#### 错误分析
- **502错误**: 465次 (46.5%) - "All search engines failed after TLB intelligent retries"
- **429限流**: 0次 (0%) - 限流机制未正常工作

#### P99响应时间详细分析

| 测试场景 | 总请求数 | P99响应时间 | P99对应请求数 | 平均响应时间 | P99/平均比值 |
|----------|----------|-------------|---------------|--------------|--------------|
| **低并发测试** | 50 | **14.318秒** | 0.5个请求 | 1.785秒 | 8.0倍 |
| **中等并发测试** | 150 | **15.286秒** | 1.5个请求 | 7.733秒 | 2.0倍 |
| **高并发测试** | 300 | **13.847秒** | 3个请求 | 2.419秒 | 5.7倍 |
| **极限并发测试** | 500 | **14.325秒** | 5个请求 | 2.523秒 | 5.7倍 |

**关键发现**:
1. **P99响应时间极高**: 所有场景的P99都在13-15秒之间，远超可接受范围
2. **响应时间分布极不均匀**: P99与平均响应时间差距巨大，说明存在严重性能瓶颈
3. **P99请求数量很少**: 只有1%的请求达到P99响应时间，但影响用户体验
4. **问题根因**: 令牌桶耗尽、重试机制、引擎切换延迟、网络超时

**优化后预期P99**:
- **目标P99**: 5-8秒 (比当前减少40-50%)
- **目标P95**: 3-5秒  
- **目标平均响应时间**: 1-2秒

### 关键指标

#### 1. 总体统计
- **总请求数**: 测试期间发送的总请求数
- **成功请求数**: 返回200状态码的请求数
- **失败请求数**: 返回非200状态码的请求数
- **成功率**: 成功请求占总请求的百分比
- **吞吐量**: 每秒成功处理的请求数

#### 2. 响应时间统计
- **平均响应时间**: 所有成功请求的平均响应时间
- **中位数响应时间**: 50%请求的响应时间
- **P95响应时间**: 95%请求的响应时间
- **P99响应时间**: 99%请求的响应时间

#### 3. TLB性能分析
- **RPS限制**: 实际RPS与期望RPS的对比
- **限流触发**: 429状态码的触发次数和比例
- **负载均衡**: 各引擎使用分布的均衡程度
- **令牌使用**: 各引擎令牌桶的使用情况

#### 4. 引擎使用统计
- **引擎分布**: 各搜索引擎的使用次数和比例
- **负载均衡比例**: 最小使用量/最大使用量
- **引擎可用性**: 各引擎的可用状态

### 性能评估标准

#### 优秀性能指标
- 成功率 ≥ 95%
- 平均响应时间 ≤ 2秒
- P95响应时间 ≤ 5秒
- 负载均衡比例 ≥ 0.8
- 限流触发率 ≤ 5%

#### 可接受性能指标
- 成功率 ≥ 90%
- 平均响应时间 ≤ 5秒
- P95响应时间 ≤ 10秒
- 负载均衡比例 ≥ 0.5
- 限流触发率 ≤ 10%

## 🚨 注意事项

1. **生产环境**: 压测工具仅用于测试环境，不要在生产环境使用
2. **资源消耗**: 高并发测试会消耗大量系统资源，注意监控
3. **API限制**: 注意第三方API的调用限制，避免超出配额
4. **数据安全**: 测试数据不要包含敏感信息
5. **网络影响**: 网络延迟会影响测试结果，建议在本地环境测试
